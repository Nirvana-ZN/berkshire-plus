# Epic 2 Context: 选股到可复盘结论

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

交付选股到可复盘结论：作者提交行业 / 指数 / 主题后，只在解析出的成分上做去劣与漏斗，得到带淘汰理由的三态名单和最多三家终选；默认对终选产出可再打开的 Checklist 与决策备忘录。通过或灰色地带可进观察池，真正买入仍须手记。重任务锁与进度在本史诗落地。四大师不挡主路径、不纳入本史诗交付。

## Stories

- Story 2.1: 按范围跑漏斗得到三态名单
- Story 2.2: 终选 Checklist 与决策备忘录
- Story 2.3: 观察池与预填记账

## Requirements & Constraints

- 范围类型为行业、指数或主题。只在解析出的成分集合上做去劣与漏斗。指数与主题必须解析到明确成分列表；失败则本轮失败，错误原文可展示，不编名单、不降级全市场、不提供手工成分表。成分或财务接口整体不可用：同样整轮失败。单家缺字段或窗口不足：该行为数据不足，任务可以完成。禁止把成分快照 JSON 当主交互。v1 只做 A 股与人民币。去劣阈值写死，运行时不让用户改。
- 去劣三态：可进漏斗候选 / 淘汰 / 数据不足。淘汰必须有理由。缺「可解析 A 股代码、市值、至少 1 年 ROE、至少 1 年净利润」任一项 → 整家数据不足，不得进保留名单、不得进终选。单条指标样本年为 0 只把该条标不足，不单独把整家打成数据不足。需要 N 年时用「上市以来可得、至多 N 年」，不因年数不够把该条标不足。第 7 条无法识别是否并购：该条标不足，不因此淘汰。
- 去劣排除（命中且无豁免 → 淘汰）：(1) 10 年平均 ROE < 8%；(2) 5 年累计自由现金流为负；(3) 利息覆盖 EBIT/利息 < 2（银行/保险跳过）；(4) 近 5 年平均毛利率 < 15%；(5) 5 年均值经营现金流/净利润 < 0.7；(6) 近 10 年平均净利率 < 5%；(7) 5 年总股本膨胀（非并购）> 20%。豁免 A 仅第 1 条：上市不足 10 年，且近 5 年或可得年份平均毛利率 > 30%，且最近 2 年经营现金流为正。豁免 B 仅第 6 条：近 5 年或可得年份平均毛利率 > 30%，且近 2 年净利率已 ≥ 5% 或明确上升。豁免 C 针对第 4 与 6 条：可得年份 ROE 均值 > 20%，且 OCF/NI > 1.0，且商业模式为高周转薄利 / 会员 / 平台佣金；无法判断则不给 C。
- 只从去劣未淘汰、非数据不足的集合按固定全序取最多十家为保留名单；其余候选淘汰，理由为「未进入本轮保留名单」。全序：市值降序 → 可得年份 ROE 均值降序 → 经营现金流/净利润降序 → 已持仓同一行业的靠后。不足十家则全部进入。选股页用三张表展示保留 / 淘汰 / 数据不足。
- 用规则把保留名单打入角色桶，再取最多三家不同名称作为终选；只来自保留名单；数据不足不进终选；不足三家有多少评多少，不凑数。打标顺序：高确定性 → 高弹性 → 中弹性，每家只进一个桶。高确定性 = 可得年份 ROE 均值 ≥ 15% **且** 市值位于保留名单从大到小前 `floor(n/3)` 名。高弹性 = 尚未入桶，且（市值位于最后 `floor(n/3)` 名，**或** 快照含 PEG 且 PEG ≥ 1.5，**或** 行业名包含：有色、煤炭、航运、证券）；无 PEG 则忽略 PEG 支路。其余为中弹性。`n<3` 时不做市值分位：能打标则打，否则全部中弹性，再按保留名单全序取终选。每桶取该桶内、按全序最前、尚未入选的 1 家；桶空或都已入选则从尚未入选的保留名单按市值从大到小补 1 家。
- 可只要漏斗名单、不自动跑 Checklist：终选仍打标可见，但不创建评估产物。默认对终选自动评估。只筛名单不因无密钥而失败。
- 对终选给出可查询结构化评估：结论仅为通过 / 不通过 / 灰色地带；六关每关通过 / 失败 / 灰色 + 一句理由；镜子测试五句，不完整则不得为通过；价格带为激进 / 稳健 / 保守或观望；备忘含生意本质、主要风险、仓位角色（核心 / 卫星 / 不买）；信息丰富度 A/B/C；研究日期与所用股价；必须对照当前仓回答三问（该不该进来、用什么钱买、是否叠逻辑）。财务或行情不足时结论为灰色地带，不编造数字。未配置网页搜索时仍可用已抓取财务完成，不得把「无搜索」写成「无财务」。评估页可读 Markdown 全文与结构化结论条；关闭工作台再打开仍在。默认最多对三家终选做完整 Checklist。四大师不是默认评估，不挡主路径，不纳入 v1 验收。
- 通过或灰色地带可加入观察池；不通过不能经该入口加入。同一用户名称唯一。加入不产生成交。工作台能看到观察池待办。不能从评估直接改持仓；可从评估或观察池预填记账表单，提交后走已有手记买卖。预填不写入成交账。没有一键下单或一键改目标。
- 漏斗、其默认评估、审视均为重任务，全局一把锁；漏斗与其默认评估占同一把锁。已有重任务再启动另一个被拒绝，须看到当前任务类型；第二任务不覆盖、不并行写坏第一任务产物。现价刷新与手工价不占这把锁。提交后能看到进行中；完成后看到产物或失败原因。漏斗若附带默认评估：能看到这一轮漏斗与其下最多三个评估子任务的状态。未配置模型密钥时，需要模型的评估不能成功完成，并指向设置，不生成假装完整的结论。某个评估子任务失败不推翻已完成的漏斗名单。
- 外部成分/财务失败必须失败可见，不得静默空名单。建议停在纸面上；禁止编造财务与行情数字；不做收益排行榜或「今日推荐」。中文 UI；主页面可见免责声明。数据与密钥留在本机。实现者不阅读或对齐 Desk。重任务允许后台进行但必须能看到状态。

## Technical Decisions

- **模块：** `jobs` 在选股任务中调 `market` 取成分与财务；`screen` 只消费已落地的成分快照与财务缓存，输出 `keep` / `drop` / `insufficient` 与淘汰理由，不 import HTTP/LLM，不生成投资建议文案。终选规则打标先于任何评估模型。`research` 不 import `ledger`，由 `jobs` 注入只读 `BookSnapshot`；只写 `research_jobs` / `research_artifacts` 与 `reports/` Markdown，不写成交 / 现金 / 目标。观察池由 `app` 读写，不经 `ledger` 写 API，也不是评估的副作用。预填后提交走 `ledger`。出站一律 `httpx2`；LLM 为 OpenAI 兼容 HTTP，不引入官方 openai SDK。行情现价走腾讯；成分与财务走东方财富公开接口。可选网页搜索未配置时评估仍用已抓取财务。
- **失败语义：** 成分名单解析不到明确列表，或财务接口整体不可用：本轮选股任务失败。单家缺字段或窗口不足：该行 `insufficient`，任务可以 `done`。FCF = 经营现金流 − 资本开支。
- **锁与进度：** `job_lock` 全局一行。默认立即返回 job id，前端轮询；`sync=true` 仅测试。第二任务 HTTP 409，正文含当前任务类型。漏斗为父任务，`research_jobs.screen_run_id` 指向该轮，API 能列出最多三个评估子任务。状态为 `queued` / `running` / `done` / `failed`。`GET /api/health` 含锁状态。启动清理残留锁。无密钥时评估 400 并指向设置。
- **数据：** `screen_runs` / `screen_results`（`verdict` 为 `keep|drop|insufficient`；`metrics_json` 含 `role` 与 `finalist`）。`watchlist` 同一用户 `name` 唯一。`financials` 键为 `code` + `period` + `period_type`（`annual` 或 `interim`）。成分快照至少 `code` `name` `mcap` `pe` `industry`，可选 `peg`；`listed_year` 在 `instruments`。评估 `structured_json` 必含：`verdict` `gates` `mirror_test` `price_bands` `memo` `data_grade` `as_of` `portfolio_fit`（三问）。持久化英文：去劣 `keep`/`drop`/`insufficient`，结论 `pass`/`fail`/`gray`；UI 中文。
- **API：** 前缀 `/api`。至少：`POST /api/screens/funnel`（`scope_type`、`scope_text`、`evaluate`）、`GET /api/screens/{id}`（漏斗状态 + 关联评估子任务）、`POST /api/research`（本史诗走 Checklist 备忘录）、watchlist CRUD、`GET /api/jobs` 与 `GET /api/jobs/{id}`。错误体 `error`/`code`/`detail`。锁 409；无密钥 400。路由：`/screen`、`/research/:id`；工作台可见锁状态、最近任务与观察池待办。
- **测试：** Fake market + Fake LLM，不打真行情/真模型。覆盖去劣/漏斗固定 fixtures（`drop` / `insufficient` / `keep`、淘汰理由、终选不重复）、锁 409、无 Key 评估 400、结构化字段入库。只筛名单不因无密钥失败。
- **本史诗不做：** 审视产物、四大师入口、运行时改阈值、主题失败时的手工成分表、一键下单或一键改仓。

## UX & Interaction Patterns

- 选股页：范围输入与进度（漏斗 + 评估子任务）；保留 / 淘汰 / 数据不足三表，淘汰与数据不足均可见理由；终选与评估入口。主路径是表格、名单与结构化结论条，不是对话窗口或原始 JSON。
- 评估页：Markdown + 结构化结论条（结论、价格带、镜子测试、对照实盘三问）。同一产物可再次打开。
- 工作台：任务锁状态、最近任务、观察池待办。进行中与完成/失败可区分；失败时错误原文可读。
- 观察池：不通过不能经该入口加入。预填记账带出名称等信息，提交前不改持仓。每个主页面可见「不构成投资建议」。

## Cross-Story Dependencies

- 依赖 Epic 1：工作台与选股入口已开、设置可配密钥、`BookSnapshot` 可注入、手记买卖可提交、现价刷新不占本史诗的锁。
- 2.1 先落地漏斗、三态名单、终选打标与重任务锁；本故事不调 LLM、不创建 Checklist。2.2 在终选上跑默认评估（或 `evaluate=true`），与 2.1 共一把锁；只筛路径不因无密钥失败。2.3 只接受 2.2 的通过或灰色地带，预填提交走 Story 1.3。
- 漏斗下某个评估子任务失败不推翻已完成名单。Epic 3 审视将占用同一把全局锁，本史诗不实现审视。
