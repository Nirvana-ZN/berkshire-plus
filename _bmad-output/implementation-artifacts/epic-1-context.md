# Epic 1 Context: 本机看仓工作台

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

交付本机单用户看仓工作台：打开即可一次性迁入 YAML 成交账，看见由成交派生的持仓与现价，手记买卖，设定目标仓位与规则灯，并在设置中配好模型密钥。选股入口必须可达且与看仓对等；漏斗、评估与审视在后续史诗。作者不必登录、不必先开 Cursor 就能每周看清这份实盘。

## Stories

- Story 1.1: 打开本机工作台
- Story 1.2: 一次性迁入 YAML 并看到持仓
- Story 1.3: 手记买卖
- Story 1.4: 刷新现价与手工价
- Story 1.5: 设定目标仓位
- Story 1.6: 规则灯
- Story 1.7: 配置模型密钥

## Requirements & Constraints

- 本机浏览器打开即可读写，无注册/登录、不切换用户。主路径是表格，不是对话窗口。看仓与选股入口对等；本史诗只保证选股入口可达。文案中文；每个主页面可见「不构成投资建议」。v1 只做 A 股与人民币；不绑定非本机地址。建议停在纸面上；禁止编造行情数字。实现者不阅读或对齐 Desk。
- 持仓由成交按**名称**聚合：买入增加股数与成本总额，卖出按移动平均成本减少；股数为 0 则持仓消失。除一次性迁入外，没有入口可直接改股数。手记字段：日期、方向、名称、股数、价格、可选说明。买入现金减少「股数×价格」，卖出增加同等金额；v1 无佣金印花税。卖超整笔拒绝（账与现金不变，原因可读）。买入后现金为负仍整笔写入并警告，不截断股数。
- 持仓表可见名称、股数、成本、现价、市值、实盘占比、目标仓位、偏差、规则灯、浮盈亏与现金。禁止把行情 JSON 当主交互。
- 库中无成交时读取已配置 YAML 目录，一次性迁入成交、现金、规则与名称↔代码。不读 Desk 或其他应用私有格式，不把库导回 YAML。迁入现金取文件余额，不从历史成交回放。设置页能区分迁入路径以及已迁入/未迁入。
- 无独立目标文件时：迁入并刷新现价后，用当时实盘占比（含现金 `__CASH__`）作为初始目标，合计为 1；之后可改，改目标不改成交。保存时含现金合计必须等于 1（容差 `1e-6`），否则拒绝。无目标持仓仍出现并标「无目标」，偏差告警不算它。有目标且实盘与目标绝对偏差 > 3 个百分点时给出再平衡提示，不下单。
- 规则可查看（名称、类型、价格、可选说明），不改成交。v1 至少「加仓上限价」。规则灯仅为触及 / 未触及 / 无规则。
- 可刷新持仓现价；成功后市值、占比、浮盈亏按新价，不再标过期。失败则保留旧价并标过期（可识别），不得删持仓。代码无法解析时原因可读、不写假价；用户可填 A 股代码（如 `601166.SH`）或手工价，手工价有来源标记。
- 设置可写密钥与模型；密钥不以明文进业务表、不进 git。保存后提示须重启或已热加载。本史诗不调用 LLM。
- 成交派生、卖超、现金公式、目标合计、迁入一次必须有不依赖真实行情和真实 LLM 的测试。记账与改目标应本机秒级可见。

## Technical Decisions

- **形态：** 单进程 uvicorn，FastAPI 提供 `/api/*` 并托管 Vue 构建产物，绑定 `127.0.0.1:8765`。开发时 Vite 代理 `/api`。前端 `web/`：create-vue 3.23.0，TypeScript + Vue Router，不上 Pinia，跨页用组合式函数。Node `^22.18` 或 `>=24.12`。后端 Python `>=3.12,<3.15`，FastAPI 0.141.1，SQLAlchemy 2.0.52，SQLite `data/app.db`，v1 `create_all`，写串行。出站一律 `httpx2`。启动确保 `users.id = 1`。`.env` 与 `data/app.db` gitignore。
- **模块：** `web` 只经 REST 进 `app`。写成交/现金/目标/规则只能 `ledger`；`ledger` 不拉行情、不调 LLM，只读已写入的 `quotes`。`migrate` 写成交、现金、规则与 `instruments`，不写 `position_targets`。`market` 做代码解析与现价 HTTP，不写 `instruments`（返回代码后由 `app` 经 `ledger` 落表）。启动编排由 `app`：库中无成交则 `migrate` → 现价刷新 → `ledger` 按当时实盘占比（含现金，允许 stale）写初始目标。
- **映射与快照：** `instruments` 是名称↔代码唯一权威。`quotes.code` 复制自 `instruments`。看仓与后续 jobs 共用只读 `BookSnapshot`（名称、股数、成本、现金、目标、无目标标记、规则灯、现价、`stale`、`__CASH__`），禁止第二套市值口径。规则灯必须进入快照。现价刷新与手工价是同步请求，不占重任务锁。过期态须能被后续审视读成无法判断。
- **约定：** 账本主键是名称；代码后缀 `.SH` / `.SZ` / `.BJ`。日期 ISO。金额与股数用 `Decimal` / SQLite `NUMERIC` / JSON number。现金 `CNY`。YAML 路径 `PORTFOLIO_YAML_DIR`；夹具仅 `tests/fixtures/portfolio/`（中文键：成交日期/方向/名称/股数/价格，现金 `余额`，规则名称/类型/价格/说明，symbols 映射）。迁入完成记在 `settings`。非密钥开关可进 `settings` 表；密钥只写 `.env`。
- **API：** 前缀 `/api`。错误体 `error`/`code`/`detail`。持久化英文：`buy`/`sell`，规则灯 `hit`/`clear`/`none`；UI 中文。卖超、目标合计不为 1、无代码 → 400。现金不足 → 2xx + `warning`。本史诗至少：health、持仓总览、记账、改目标、规则、刷新行情、手工价/补代码、settings。路由：`/`、`/positions`、`/screen`、`/settings`。
- **测试：** Fake market；覆盖买/卖/均价/卖超/现金警告、目标合计与容差、偏差 3 个百分点、迁入笔数/现金/只迁入一次。
- **本史诗不做：** 漏斗、Checklist、观察池、审视、重任务锁验收、无密钥评估 400、四大师、佣金、Alembic、Pinia。Vue 组件库由第一个 web 故事选定后复用。

## UX & Interaction Patterns

- 打开无登录页；工作台同时可见看仓与选股入口。主交互是持仓表，不是聊天或原始 JSON。
- 只有手记买卖，没有「直接改股数」。卖超原因可见；现金不足警告与成交同时出现。
- 过期价可识别；手工价与自动行情可区分。无目标行标「无目标」。再平衡提示不下单。规则灯中文三态。免责声明在每个主页面可见。
- 设置：保存密钥后提示重启或已热加载；迁入路径与已迁入/未迁入可区分。

## Cross-Story Dependencies

- 1.1 提供进程、路由、health、`users.id = 1`、中文与免责、双入口。
- 1.2 迁入是 1.3–1.6 真实数据路径的前提。
- 1.3 成交公式是日常持仓与现金真相；1.5 改目标不得改成交。
- 启动顺序：迁入 → 现价刷新 → `ledger` 写初始目标（允许 stale）。1.4 的过期态供 Epic 3 读成无法判断。
- 1.6 规则灯进入 `BookSnapshot`，供 Epic 3 对照。1.7 密钥供 Epic 2/3；本史诗不调模型。选股入口可达，漏斗在 Epic 2。现价刷新不占 Epic 2 的锁。
